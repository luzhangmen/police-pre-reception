# 大作业呈现与创新指南（校园警务预接待系统）

面向答辩 / 课程展示，建议把「能跑」升级为「能讲故事、能对比、能度量」。

## 1. 推荐演示叙事（8–10 分钟）

| 环节 | 时长 | 内容 | 亮点 |
|------|------|------|------|
| 痛点 | 1 min | 口语冗长、信息不全、民警重复登记 | 放一段「数字人接待」原话 |
| 对比 | 2 min | 同一段话：原话 → 结构化字段 → Word 信息单 | 展示 `generate_showcase_demo.py` 输出 |
| 闭环 | 3 min | 输入 → reason → 追问 → 风险 → 文档下载 | 现场 Swagger 或前端 |
| 安全 | 1 min | 高风险案例 handoff、止付话术 | fraud-002 类案例 |
| 创新 | 2 min | 见下文「可写进论文的创新点」 | 多模态情绪 + 完整度评分 |
| 指标 | 1 min | 评测脚本结果表（瞿逸凡模块） | 场景准确率、漏判率 |

## 3. 案例库要不要变复杂？

**要，但要分层，不要一味堆难。**

建议把 `demo_cases.json` 扩成三档：

1. **L1 标准句**：信息齐全，用于证明「端到端稳定」。
2. **L2 口语冗长**（新增）：含嗯、那个、反复、情绪词，用于证明「抽取 + 文档润色」价值。
3. **L3 边界/对抗**（少量）：场景模糊、多事件、反讽，用于论文讨论局限。

每条 L2 案例建议增加字段：

```json
"colloquial_input": "那个……警官……",
"expected_slots": { ... },
"document_narrative_keywords": ["图书馆", "疑似被盗"]
```

流程应是：**复杂口语 → pipeline 抽 slots → 文档模块润色填入模板**，而不是手写进 Word。

## 4. 模块分工与「表现力」增强

| 模块 | 答辩一句话 | 可视化建议 |
|------|------------|--------------|
| 文本 pipeline | 四类场景 + 完整度 + 风险 | 警方侧字段表 + 风险色条 |
| 多轮追问（陈誉） | 像接待而不是问答机 | 三轮对话录屏 |
| RAG（何达煜） | 建议可解释、可引用 | 展示 snippet 来源 |
| 文档（陆宣辰） | 原话进、信息单出 | 左右对比 PPT |
| 评测（瞿逸凡） | 用数据证明有效 | 柱状图 / 表格 |
| 前端（张圣康） | 群众侧 + 警方侧双视角 | 分屏演示 |

## 5. 可写进论文/答辩的创新点（选 2–3 个深挖）

1. **双通道摘要**：群众侧安抚话术 vs 警方侧事实摘要（同一 CaseState，不同呈现）。
2. **完整度驱动的对话策略**：不完整则追问，完整则指引，高风险则 handoff（规则 + LLM 混合）。
3. **预受理信息单自动生成**：从非结构化口语到可归档 Word，减少民警重复录入（你的模块核心卖点）。
4. **知识库增强处置建议**：关键词 → RAG，文档中可展示「依据哪条 KB」。
5. **多模态情绪融合**（若张圣康模块就绪）：语气影响数字人表现参数。

避免空泛宣称「用了大模型」；强调 **可解释、可评测、可落地校园场景**。

## 7. 局限与展望（答辩加分）

- 口语极度含糊时仍依赖 LLM 抽取质量。
- 正式笔录与法律文书需民警审定，系统定位为**预受理辅助**。
- PDF 签章、公安内网对接可作为未来工作。
