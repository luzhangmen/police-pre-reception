## 3. 案例设计要点（组长/组员可快速扫）

### 3.1 单轮案例（`demo_cases.json`）

每条至少包含：

- `id`、`scenario`、`input`（用户原话）
- `expected_risk`、`expected_slots`、`expected_missing_fields`
- `expected_next_question`（及 `expected_next_question_keywords`）
- `expected_completeness`、`expected_next_action`、`expected_emotion`（按需）

标签覆盖：`demo_star`（演示推荐）、`boundary`（易混淆）、`high_risk`、`sparse_input`、`handoff` 等。

### 3.2 周末演示推荐（★ 8 条）

见 `docs/week1_demo_cases.md` 第 2 节，例如：

- `fraud-001`、`fraud-002`：抽取 + 高风险 handoff
- `loss-003`、`loss-007`：证件风险 / 完整度 1.0
- `conflict-003`、`conflict-008`：肢体冲突 / 情绪
- `threat-001`、`threat-008`：即时危险 / 校外滋扰

张圣康集成演示时可直接引用该表。

### 3.3 笔录库（三类口语场景）

- 诈骗 → 系统 `telecom_fraud`
- 盗窃 → `property_loss` + `suspected_theft: true`
- 打架 → `dorm_conflict` + `physical_conflict: true`

用于测 **长文本抽取**、**警方摘要**（`body` / `plain_summary`），与短句口语案例互补。

## 5. 如何复现与验收

```bash
cd backend

# 校验案例与笔录
python -m pytest tests/test_demo_cases.py tests/test_demo_dialogues.py -v
python -m pytest tests/test_demo_transcripts.py tests/test_demo_transcript_variants.py -v

# 全量（推荐组长验收用）
python -m pytest tests/ -q

# 重新生成笔录（改脚本后）
python tests/scripts/build_transcripts_three_scenarios.py
python tests/scripts/build_transcript_variants.py
```

单条 pipeline 冒烟（示例）：

```python
from app.core.pipeline import run_pipeline
from app.core.state import UserMessage

state = run_pipeline(UserMessage(
    text="我在闲鱼买演唱会票被骗了，微信转了480，对方把我拉黑了",
    case_id="fraud-001",
))
print(state.scenario, state.risk_level, state.completeness_score, state.next_action)
```
